Vibe Coding 范式：数据与逻辑先行，用 AI 从 0 到 1 打磨一款 App

发表于2026-09-11|更新于2026-09-11|AI
|总字数:4.2k|阅读时长:13分钟|浏览量:

前言

Vibe Coding 不是"把需求扔给 AI 然后祈祷"。它有范式，有节奏，有先后顺序。踩过坑的人都会收敛到同一条关键原则上：

数据与逻辑先行，UI 与视觉跟进，最后细节提质。

顺序反了会发生什么？你会陷入两种经典窘境：

  • UI 做好了，数据对不上——界面精美，但 Anki 导出的字段和 UI 组件对不上号，推倒重来；
  • 功能都有了，但一股"AI 垃圾感"——组件堆砌、间距随意、毫无原生 App 质感。

这条笔记以我开发日语学习 App kogo（コゴ）（N1-N5 学习软件，Expo + React Native）为例，把 Vibe Coding 一个完整软件的流程拆成四个阶段，做成范式。你换成任何 App，流程不变。

角色分工：给 AI 排好座位

在开始之前，先明确 AI 编程 Agent 里两类"员工"的职责：

角色承担工具职责
首席 UI/UX 设计师与视觉审查官Impeccable产品规范、设计语言、页面规划、视觉迭代、动效、无障碍审查
首席技术架构师与数据工程师Superpowers（及 AI Agent 的架构/工程能力）技术架构文档、数据清洗脚本、数据库设计、底层服务层

一句话：Impeccable 管长什么样，Superpower 管怎么运转。 两者配合的顺序，就是下面四个阶段。

具体的分工口诀：

  • 没有界面的代码（数据清洗脚本、DB 层、Hook、状态管理、算法）→ Superpowers 工程流程：brainstorming → writing-plans → TDD 实现 → code review
  • 有界面的代码（页面、组件、交互、动效）→ Impeccable 设计流程：shape → craft → harden → polish

Superpowers 的安装与技能清单见我之前的《给 AI 编程助手装上「超能力」》，本文只讲它怎么嵌进 Vibe Coding 流程。

第一阶段：顶层设计与上下文建立（AI 统一大脑）

在写第一行具体代码之前，先让 AI 明确产品的全貌与设计语言。这一步的产出不是代码，而是上下文——后续所有 AI 对话都基于它，避免每次对话都重新解释一遍产品是什么。

Step 1.1: 运行 Impeccable 建立产品与设计规范

在项目根目录运行（注意：v3.x 起该命令已由 init 改名为 teach，网上旧教程里的 /impeccable init 与它是同一个东西）：

它默认是交互式的：采访你的产品定位、用户、品牌个性、无障碍需求，最后写出 PRODUCT.md（战略层：谁用、为什么用）与 DESIGN.md（视觉层：长什么样）。

更省事的姿势：直接接 prompt，跳过大部分采访。 命令名后面的所有文字都会作为目标上下文传入，而 teach 的原则是"只问代码库和已有材料里推不出来的问题"。所以如果你手上已经有一份大纲文档（PRD、竞品分析、功能清单都行），先放进仓库，再一句话点名：

大纲写得越完整，采访轮次越少；信息全齐时它会直接给出草稿让你确认（写文件前一定让你点头，不会静默覆盖已有文件）。

无论走交互采访还是喂文档，都要确保它拿到这些信息：

  • 产品定位：日语 N1-N5 学习软件 kogo（コゴ），极简、高效、专注沉浸。
  • 主要模块：四大 Tab 屏（学习主页、训练页、错题回顾页、我的页）。
  • 特殊 UI/UX 需求：
    • 假名注音（Furigana / 振仮名）渲染支持
    • 音频/图片媒体卡片交互（播音反馈、看图测验）
    • 移动端（iOS/Android）原生体验，基于 Expo + NativeWind

Step 1.2: 使用 Superpowers 撰写技术架构文档

设计语言有了，接着让 Superpowers 梳理工程骨架。注意：Superpowers 没有斜杠命令，直接在对话框里说需求，相关技能会自动触发。它的标准流程是：brainstorming 先苏格拉底式追问把技术选型聊透（设计没定稿前 <HARD-GATE> 会拦住实现代码，一行都不让写），定稿后由 writing-plans 落成任务拆解，产出 ARCHITECTURE.md。

在对话框里直接发：

常见问题：teach 之后觉得设计不合适，需要二次调整吗？

必须调整。 /impeccable teach 生成的只是 AI 基于初始提示词或大纲给出的"第一版草稿"，不是不可动摇的最终定稿。

为什么必须二次调整：

  • 业务细节补全：AI 在初始化时会自行填充很多"看起来合理"的逻辑，但这些假设往往缺乏你对具体业务场景、用户偏好或技术限制的理解；
  • 规避重构成本：带着不合格的设计进入代码生成阶段，后续微小的逻辑修改都会引发大量组件或接口的重构。

高效二次调整的姿势：

  1. 直接修改源文件：打开 PRODUCT.md / DESIGN.md，手动修正核心流程、交互逻辑与数据结构；
  2. 精准指令覆盖：针对不满意的点向 AI 发出具体指令（例如："修改用户注册流程，移除邮箱验证，改为纯手机号加验证码登录"），要求它同步更新设计文档；
  3. 重点审查边界：主流程逻辑是否通畅、异常状态是否有定义、页面元素是否冗余或缺失。

在产品设计阶段多花 5 分钟精雕细琢，能省去后续写代码时几小时的反复扯皮。确定设计符合预期后，再进入下一阶段。

第二阶段：数据工程与底层服务（Data Pipeline & SQLite）

这是最关键的一步。 在没有搞定数据格式之前，不要盲目去写复杂的 UI。

Step 2.1: 数据清洗与 SQLite 导出脚本

让 AI 帮你写一段本地 Python 或 Node.js 脚本，清洗源数据。以 kogo 的 Anki 牌组为例，在对话框里直接发：

最后一句是关键——让它先对齐规则再动手，缺音频、HTML 嵌套、重复卡片这些边界都写进测试。

范式要点：你的"原材料"是什么格式、目标数据库长什么样，先在这一步定死。 脚本跑通、数据落库、抽查无误，才继续往下走。

这一步全程走 Superpowers 流程：脚本也是代码，直接丢给它走 brainstorm → plan → TDD 循环，把清洗规则的边界（缺音频、HTML 嵌套、重复卡片）用测试钉死，避免"跑一遍对一遍、换个牌组又炸"。

Step 2.2: 搭建数据与媒体服务层

在 RN 中编写 DB 操作和音频播放的核心工具。同样直接发需求：

  • DB 接口：使用 expo-sqlite 实现分层查询（按 N1-N5 筛选、按错题筛选、随机抽取训练题）；
  • Audio 播放器：使用 expo-audio 封装一个 useAudioPlayer Hook，支持日语例句/单词点击即播，支持 0.8x / 1.0x / 1.2x 语速切换（对 JLPT 听力训练极度重要）。

这一层是纯逻辑代码，不经过 Impeccable——同样走 Superpowers 的 TDD 流程实现，查询与播放逻辑用测试说话。

这一步结束时，你应该可以在一个空白测试页里：查出一个单词 → 点一下播出音频。数据/逻辑 Hook 全部 Ready，是进入 UI 阶段的前置条件。

第三阶段：分模块 Vibe Coding（Shape → Craft）

数据层和 Hook 通畅后，开始用 Impeccable 的两步法逐步完成各个页面模块。核心节奏：

传参规则：命令名后面的所有文字都是 target，可以是中文需求描述、英文代号或文件路径。想省一步也可以直接 /impeccable craft <完整需求描述>（craft 内部会先跑 shape，等你确认简报后再动手）。

以 kogo 的四大 Tab 为例——注意这个循环对每个模块都是一样的，一次只攻克一个 Tab：

一个 Tab 里如果混着纯业务逻辑（比如错题本的遗忘曲线排序算法、打卡统计），先走 Superpowers 的 TDD 循环把逻辑实现并测好，再交给 Impeccable 做界面。逻辑归 Superpowers，皮归 Impeccable。

1. 学习页（Home Tab）——核心卡片与刷题

2. 训练页（Practice Tab）——专项与模拟考

3. 错题回顾页（Mistake Review Tab）——针对性复习

4. 我的页（Profile Tab）——数据可视化与设置

第四阶段：移动端体验强化与打磨（Hardening & Polish）

各模块初步完成后，针对移动端（Expo/RN）的特点做深度优化。

总结：Vibe Coding 指南针

步骤任务内容推荐工具 / 指令交付物
Phase 1初始化产品与设计规范/impeccable teach（旧名 init）PRODUCT.md, DESIGN.md
Phase 2数据清洗与 SQLite 预置Superpowers（brainstorm → plan → TDD）kogo.db, useSQLite, useAudio
Phase 3各页面模块逐个攻克/impeccable shape ➔ /impeccable craft各 Tab 基础代码
Phase 4移动端抗摔测试（边缘情况）/impeccable harden <Tab>高健壮性的 RN 页面
Phase 5动效与视觉精修/impeccable animate / /impeccable audit具备原生 App 质感的成品

按照这个顺序，你既不会陷入"UI 做好却对不上数据"的窘境，也不会写出"充满了 AI 垃圾感"的劣质界面。

附录：Impeccable 全部 23 个指令速查

以下按官方 README 的功能分组列出，附使用场景，供各阶段按需取用。所有指令的用法都一样：/impeccable <指令> <target>，target 可以是页面/组件名、文件路径或整段需求描述，不带参数则弹出菜单让你选。

1. 架构与初始化（Setup & Strategy）

指令使用场景
/impeccable teach（旧名 init）新项目刚启动时使用。分析项目、提问补全关键产品上下文，写出 PRODUCT.md；也可直接后接大纲文档路径非交互生成
/impeccable document接手已有代码的项目时使用。扫描已有前端代码，反向生成全局设计规范 DESIGN.md
/impeccable shape在编写任何组件或 UI 代码之前使用，规划 UX 流程、页面结构和交互图谱

2. 布局与视觉美化（Visual & Layout Tweaks）

指令使用场景
/impeccable layout页面布局凌乱、间距不统一、对齐有问题或视觉节奏差时使用
/impeccable typeset字体选型不好看、文字层级不清晰、字号或行高不合适时使用
/impeccable colorize界面过于单调（纯黑白/全灰色），需要策略性引入主题色、高亮色、渐变色时使用
/impeccable bolder界面太平淡、像大众化模板、缺乏设计冲击力时使用（放大重点、增强对比）
/impeccable quieter界面太花哨、元素堆叠严重、主次不分时使用（收敛视觉，让界面变沉稳）
/impeccable distill信息过载、视觉杂质太多时使用（做减法，精简到最核心要素）

3. 交互、动效与亮点（Interaction & Delight）

指令使用场景
/impeccable animate状态切换、展开收起或页面跳转显得生硬时使用，添加符合物理直觉的过渡与微动效
/impeccable delight在关键路径（支付成功、表单提交、空状态完成）上增加小彩蛋或愉悦微交互
/impeccable overdrive打造极其惊艳的 Landing Page、官网首页或展台时使用，加入 3D、复杂 Shader 等硬核特效

4. 体验细节与边缘情况（UX & Edge Cases）

指令使用场景
/impeccable onboard开发新用户首次使用引导、无数据空状态（Empty States）或激活流程时使用
/impeccable clarify按钮文案晦涩、报错提示不清晰时使用，重写为易懂的文案
/impeccable harden提交代码前的防错治理：异常报错 UI、超长文本截断溢出、多语言（i18n）适配等
/impeccable adapt页面在移动端、平板或大屏上出现断层或错位时使用，进行响应式适配优化

5. 审查、重构与交付（Review & Shipping）

指令使用场景
/impeccable critique让 AI 扮演资深 UI/UX 设计师，对视觉层级、清晰度与情感共鸣做设计评审
/impeccable audit运行技术质量检查，自动化评估无障碍（a11y）、响应式规范与性能隐患
/impeccable extract代码写乱或重复代码较多时，提取重复 UI 为可复用组件与 Design Tokens
/impeccable optimize遇到 UI 渲染卡顿、DOM 树过深、重绘重排严重等性能瓶颈时使用
/impeccable polish上线交付前的最后一道工序，统一全局设计规范并打磨像素级细节

6. 综合全流程与实时模式（Full Flow & Live）

指令使用场景
/impeccable craft全流程综合大招，自动串联"规划 (Shape) ➔ 构建 (Build) ➔ 视觉迭代 (Visual)"完整闭环
/impeccable live配合浏览器插件使用，开启可视化变体模式，实时生成并对比多种 UI 变体方案
