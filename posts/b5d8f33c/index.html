Impeccable：给 AI 编程助手装上「设计师审美」

发表于2026-09-15|更新于2026-09-15|AI
|总字数:3.1k|阅读时长:10分钟|浏览量:

前言

让 AI 写前端，功能都能跑，但界面总有一股挥之不去的"AI 味"：Inter 字体、紫色渐变、卡片套卡片、灰字压在彩色背景上。这不是错觉——每个 LLM 都是从同一批通用模板里学出来的，没有引导，你就会得到同样可预测的错误。

Impeccable 就是治这个的。它基于 Anthropic 官方的 frontend-design skill 深化而来，一句话概括：

1 个 skill + 24 个命令 + 一整套反模式清单，让 AI 写出有设计师审美的高质量前端。

这条笔记是我使用 Impeccable 的完整整理（基于官方仓库最新版，npm 已迭代到 v4.x）：定位、安装、上下文体系、24 个指令全解、使用技巧与避坑。它在我的 Vibe Coding 范式里承担"首席 UI/UX 设计师"的角色，与负责工程化的 Superpowers（见《给 AI 编程助手装上「超能力」》）正好一对——一个出皮，一个出骨。

为什么需要 Impeccable

直接让 AI"画一个好看的页面"，产出往往是通用模板缝合怪。Impeccable 从三个层面纠偏：

  1. 一个深度 skill：内置 7 份领域专属参考资料——排版（typography）、色彩与对比（OKLCH、暗色模式、无障碍）、空间设计（间距系统、栅格、视觉层级）、动效设计（缓动曲线、reduced motion）、交互设计（表单、焦点态、加载模式）、响应式设计（移动优先、容器查询）、UX 文案（按钮、报错、空状态）；
  2. 24 个命令：覆盖审查（audit）、评审（critique）、打磨（polish）、精简（distill）、动效（animate）等完整设计工作流；
  3. 反模式清单：明确告诉 AI 不要做什么——不用烂大街的字体（Arial、Inter）、不用灰字压彩底、不用纯黑纯灰（永远带色调）、不万物皆卡片、不用 bounce/elastic 弹性缓动（显得过时）。

安装

方式一（推荐）：官方 CLI 安装器，在项目根目录运行：

它会自动检测你机器上已装的 AI 编程工具，让你选择 providers（claude、cursor、codex、github 等十余种）和安装范围（项目级或全局）。之后升级只需 npx impeccable update。

方式二：插件市场。以 Claude Code 为例：/plugin marketplace add pbakaus/impeccable。

方式三（兜底）：去 impeccable.style 下载 ZIP，或从仓库手动复制 dist 目录（如 cp -r dist/claude-code/.claude your-project/）——官方 README 明确说这是调试/兜底手段，正常路径走方式一即可。

个别工具有前置条件：如 Cursor 需在设置里切 Nightly 通道并启用 Agent Skills，Gemini CLI 需装 preview 版。

核心机制：上下文先行（PRODUCT.md + DESIGN.md）

Impeccable 的一切设计工作开始前，都要先过上下文门禁：没有产品上下文就动手，产出的就是通用垃圾。

文件定位怎么来
PRODUCT.md必需。战略层：用户是谁、品牌调性、反参考、战略原则/impeccable init 生成
DESIGN.md可选但强烈推荐。视觉层：颜色、字体、高度、组件规范init 一并生成，或 /impeccable document 从已有代码反向生成

两条生成路径对应两种场景：

init 也支持非交互式——把关键信息直接写在命令后面（命令名后面的所有文字都会作为目标上下文传入），信息给得越全，采访轮次越少；信息齐了它会直接出草稿让你确认，写文件前一定让你点头，不会静默覆盖已有文件。

brand 与 product：先分清你在设计什么

Impeccable 把设计任务分成两种注册表（register），动笔前必须先识别：

  • brand（设计即产品）：营销页、官网、活动页、作品集——设计本身就是要表达的东西；
  • product（设计服务于产品）：App UI、后台、仪表盘、工具——设计是给功能让路的。

两种注册表下，同样的指令会给出完全不同的设计决策（比如 brand 可以大胆用饱和色，product 默认克制）。

24 个指令全解

用法统一：/impeccable <指令> <target>。target 可以是页面名、组件名、文件路径或整段需求描述；不带参数则弹出菜单让你选。

1. 架构与初始化（Setup & Strategy）

指令使用场景
/impeccable init（旧版曾叫 teach）新项目启动时使用。分析项目、提问补全关键产品上下文，写出 PRODUCT.md
/impeccable document接手已有代码的项目时使用。扫描已有前端代码，反向生成全局设计规范 DESIGN.md
/impeccable shape在编写任何组件或 UI 代码之前使用，规划 UX 流程、页面结构和交互图谱

2. 布局与视觉美化（Visual & Layout Tweaks）

指令使用场景
/impeccable layout页面布局凌乱、间距不统一、对齐有问题或视觉节奏差时使用
/impeccable typeset字体选型不好看、文字层级不清晰、字号或行高不合适时使用
/impeccable colorize界面过于单调（纯黑白/全灰色），需要策略性引入主题色、高亮色、渐变色时使用
/impeccable bolder界面太平淡、像大众化模板、缺乏设计冲击力时使用（放大重点、增强对比）
/impeccable quieter界面太花哨、元素堆叠严重、主次不分时使用（收敛视觉，让界面变沉稳）
/impeccable distill信息过载、视觉杂质太多时使用（做减法，精简到最核心要素）

3. 交互、动效与亮点（Interaction & Delight）

指令使用场景
/impeccable animate状态切换、展开收起或页面跳转显得生硬时使用，添加符合物理直觉的过渡与微动效
/impeccable delight在关键路径（支付成功、表单提交、空状态完成）上增加小彩蛋或愉悦微交互
/impeccable overdrive打造极其惊艳的 Landing Page、官网首页或展台时使用，加入 3D、复杂 Shader 等硬核特效

4. 体验细节与边缘情况（UX & Edge Cases）

指令使用场景
/impeccable onboard开发新用户首次使用引导、无数据空状态（Empty States）或激活流程时使用
/impeccable clarify按钮文案晦涩、报错提示不清晰时使用，重写为易懂的文案
/impeccable harden提交代码前的防错治理：异常报错 UI、超长文本截断溢出、多语言（i18n）适配等
/impeccable adapt页面在移动端、平板或大屏上出现断层或错位时使用，进行响应式适配优化

5. 审查、重构与交付（Review & Shipping）

指令使用场景
/impeccable critique让 AI 扮演资深 UI/UX 设计师，对视觉层级、清晰度与情感共鸣做设计评审
/impeccable audit运行技术质量检查，自动化评估无障碍（a11y）、响应式规范与性能隐患
/impeccable extract代码写乱或重复代码较多时，提取重复 UI 为可复用组件与 Design Tokens
/impeccable optimize遇到 UI 渲染卡顿、DOM 树过深、重绘重排严重等性能瓶颈时使用
/impeccable polish上线交付前的最后一道工序，统一全局设计规范并打磨像素级细节

6. 综合全流程与实时模式（Full Flow & Live）

指令使用场景
/impeccable craft全流程综合大招，自动串联"规划 (Shape) ➔ 构建 (Build) ➔ 视觉迭代 (Visual)"完整闭环
/impeccable live配合浏览器插件使用，开启可视化变体模式，实时生成并对比多种 UI 变体方案
/impeccable generatelive 模式下为指定元素批量生成多个变体，无需手动逐个挑选

使用技巧

技巧 1：craft 是大招，但 shape 是地基

craft 内部会先跑 shape 产出设计简报，等你确认后才动手写代码——这一步不能省、也不能跳。Impeccable 内部有硬门禁：没有用户确认过的 shape 简报，craft 不允许产出任何实现代码（init 生成的 PRODUCT.md 不算数）。所以用 craft 的正确姿势是把需求完整写在命令后面，然后认真审那份简报。

技巧 2：常用指令可以 pin 成独立快捷方式

高频指令 pin 出来，少打一半字。

技巧 3：不记得指令时，直接说人话

/impeccable 后面不跟指令、直接跟一段自然语言描述也行——skill 本身会在对话中自动触发（描述里带"设计/打磨/审查某个界面"这类意图时）。

技巧 4：不进 IDE 也能查"AI 味"——独立 CLI

这个检测器能抓 24 类问题，分两路：AI slop（侧边栏描边、紫色渐变、bounce 缓动、暗色发光）和通用设计质量（行长过长、内边距拥挤、触摸热区过小、跳级标题等）。不依赖任何 AI 编程工具，纯前端团队也能用它做 CI 检查。

技巧 5：init 的产出是草稿，必须二次调整

/impeccable init 生成的是 AI 基于大纲给出的第一版草稿，不是定稿。高效调整姿势：

  1. 直接改源文件：打开 PRODUCT.md / DESIGN.md 手动修正核心流程、交互逻辑与数据结构；
  2. 精准指令覆盖：对不满意的点发具体指令（如"注册流程去掉邮箱验证，改为手机号+验证码"），让它同步更新文档；
  3. 重点审查边界：主流程是否通畅、异常状态有没有定义、页面元素是否冗余或缺失。

产品设计阶段多花 5 分钟精雕，省去写代码后几小时的反复扯皮。

技巧 6：默认遵守的底层设计法则

Impeccable 的 skill 里有几条"共享设计法则"，了解它们能帮你理解它为什么这样改你的界面：

  • 颜色用 OKLCH：亮度趋近 0 或 100 时降低 chroma，极端亮度配高饱和会显得刺眼；
  • 永远不用纯黑 #000 纯白 #fff：所有中性色都向品牌色调微微染色（chroma 0.005–0.01 就够）；
  • 先定色彩策略再选色：克制型（tinted 中性色 + ≤10% 单强调色，product 默认）/ 承诺型（一个饱和色占 30–60% 面，brand 默认）/ 全色盘型（3-4 个明确色角色）；
  • 复杂度匹配愿景：极简需要精确，极繁需要 elaborate 的代码，别错配。

一条实用的编排心法：让外部 AI（如 ChatGPT）拿着这份 24 指令清单当流程指挥官，每次只给你"下一步"；编程 Agent 里只管执行。 外部 AI 掌全局不漏步骤，Agent 上下文干净专注执行。

总结

你想要用什么
新项目建立产品与设计规范init（旧版曾叫 teach）
老代码库反推设计规范document
一个页面从需求到成品craft（内含 shape 确认）
界面太平淡 / 太花哨bolder / quieter
交付前兜底检查audit ➔ polish
检测已有代码的 AI 味npx impeccable detect
浏览器里实时对比变体live

Impeccable 解决的是 Vibe Coding 里最容易被忽视的一环：AI 写得出功能，写不出审美。把 24 个指令当成设计师的工具箱，按需取用、按序编排，你得到的就是"充满了 AI 垃圾感"的反面。

前言Vibe Coding 不是"把需求扔给 AI 然后祈祷"。它有范式，有节奏，有先后顺序。这条笔记的核心原则是： UI 与视觉先行（mock 数据快速定型产品形态），数据与逻辑收尾（UI 定稿后再做工程化接通），细节提质贯穿全程。 为什么 UI 先行？ 产品形态看得见才好判断。界面没定型之前，任何数据工程投入都可能被 UI 改版推翻——先做数据，界面一改，清洗脚本、表结构、服务层跟着返工； 改 UI 的成本几乎为零。此阶段全部用 mock 数据，不满意就随手改，不用迁就真实数据的格式； UI OK 之后，数据工程一次投入、一次接通。此时字段需求已经完全明确（界面就是字段清单），Anki 清洗、SQLite、服务层照着界面做，不会对不上号。 如果你的数据格式已经完全定死（比如严格对接既定协议），反过来"数据先行"也成立。这里选 UI 先行，因为它对"产品还在改"的早期阶段更友好。 这条笔记以我开发日语学习 App kogo（コゴ）（N1-N5 学习软件，Expo + React Native）为例，把 Vi...
